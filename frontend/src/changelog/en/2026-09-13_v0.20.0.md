## The Same Event, On New Dates

The summer festival you ran last July is the summer festival you will run next
July. Until now the app had no opinion about that: you started an empty event
and rebuilt the cake counter, the grill, the entrance desk and the clear-down
from memory, one shift at a time, while last year's version sat right there in
your event list.

Now every event you administer has **Copy this event**. Give the copy a name and
a start date, and everything underneath moves with it — tasks, their shifts,
their times, the lot. The original is not touched. It keeps its dates, its
shifts and its sign-ups exactly as they are; what you get is a separate new
event standing beside it.

The new start date defaults to the same weekday a year on, because a festival
that ran on a Saturday needs to run on a Saturday. Move it anywhere you like and
the whole plan follows.

## You Choose What Comes Across

The second step is a list of last year's tasks with their shift counts, all
ticked. Untick the ones that are not coming back. The Kids' Corner that only
happened because somebody volunteered to run it, the stall that rained off — leave
them behind.

By default the shifts come across exactly as they were, down to the times
somebody adjusted by hand on the day. If a task should be laid out differently
this year, switch it to **Plan the shifts again** and set the hours, the length
and how many people you need; the screen shows you the shifts it would build
before anything is created.

Each task can also be adjusted on its way over — renamed, moved, re-dated — and
you can see the exact list of shifts the copy will contain before you commit to
any of it.

## What Deliberately Stays Behind

Last year's sign-ups do not come with the copy. Neither do the availability
people entered, the invitations that were still open, or anyone's requests to
join. The copy arrives with empty shifts, which is the point: it is next year's
rota, not a record of last year's.

The people, though, usually are the same people. **Bring the same people across**
is on by default and carries the roster with their roles intact, so you are not
re-inviting thirty volunteers by email. Nobody is told anything unless you ask
for it on the last step — and if you do, they get one message about the event
rather than one per task.

## A Copy Starts Quiet

Tasks come across as drafts, so nobody can book a shift in a plan you are still
working on. When a task is ready, publish it from the new event and it opens for
booking then. If you would rather a task be open from the moment the copy
exists, say so while you are setting it up.
